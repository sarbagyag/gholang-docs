gholang

A bytecode VM for Lox, in C.

gholang compiles Lox source into compact bytecode in a single pass, then runs it on a stack-based virtual machine. It is the second half of Crafting Interpreters by Robert Nystrom, written in plain C99 with no dependencies.

Build & run How it works
Single-pass compilerA Pratt parser emits bytecode directly. There is no AST.
Stack VMOne switch loop over 29 opcodes, with call frames.
ClosuresCaptured variables live on the stack until they are closed over.
SmallAbout 3,000 lines of C in src/.

What the language has

  • Numbers (double), booleans, nil and strings
  • Global and local variables with block scope
  • if / else, while, for, and / or
  • First-class functions, recursion and closures
  • A native function, clock()
Scope

This site documents the implementation through the closures chapter. Garbage collection, classes and inheritance are not in the code yet. See Status.

Get started

Build & run

You need a C compiler and make. The Makefile uses clang with -Wall -Wextra -std=c99.

git clone <your-repo-url> gholang
cd gholang
make            # builds ./gholang
./gholang script.lox

If you don't have clang, override it: make CC=gcc. make clean removes the binary.

Your first program

var greeting = "Hello";
print greeting + ", gholang!";
Debug output is on by default

src/common.h defines DEBUG_PRINT_CODE and DEBUG_TRACE_EXECUTION, so every run prints the disassembly and a stack trace before and during execution. Comment out those two lines (and rebuild) for clean output.

// #define DEBUG_PRINT_CODE
// #define DEBUG_TRACE_EXECUTION

Language

Values & types

Lox is dynamically typed. Every value is one of four kinds:

TypeLiteralNotes
Number12, 3.14Always a 64-bit double. No leading . or trailing ., and no negative literals (-1 is negation).
Booleantrue, false
NilnilThe absence of a value. Uninitialised variables are nil.
String"text"Double quotes only. No escape sequences. May span lines.

Functions are values too. They print as <fn name>, and the native clock prints as <native fn>.

Truthiness

Only nil and false are falsey. Everything else is truthy, including 0 and "".

Printing numbers

Numbers print with C's %g, so 2.0 prints as 2, and very large or small values use exponent form.

print 7 / 2;      // 3.5
print 10 / 5;     // 2
print 1 / 0;      // inf

Equality

== compares type first, so values of different types are never equal (0 == false is false). Strings compare equal when their contents match, because they are interned.

Language

Variables & scope

var a;            // nil
var b = 10;
b = b + 1;        // assignment is an expression

{
  var c = "local";
  print c;
}
// print c;       // runtime error: Undefined variable 'c'.

Globals vs. locals

Where a variable is declared decides how it's stored:

  • Global (top level) variables live in a hash table, looked up by name at runtime. You can redeclare a global; assigning to one that was never declared is a runtime error.
  • Local variables (inside a block or function) live on the VM stack and are resolved to a slot number at compile time. There's no name lookup at runtime.
Rules the compiler enforces

A local can't be redeclared in the same scope (Already a variable with this name in this scope.), and can't be read in its own initializer (Can't read local variable in its own initializer.). A function has at most 256 local slots.

Language

Control flow

if (x > 0) print "positive"; else print "not positive";

var i = 0;
while (i < 3) { print i; i = i + 1; }

for (var j = 0; j < 3; j = j + 1) print j;

All three for clauses are optional. The initializer can be a var declaration or an expression. A variable declared there is scoped to the loop.

There's no break, continue or switch. Under the hood all of this compiles to OP_JUMP, OP_JUMP_IF_FALSE and OP_LOOP.

Language

Functions

fun fib(n) {
  if (n < 2) return n;
  return fib(n - 1) + fib(n - 2);
}

print fib(10);   // 55
print fib;       // <fn fib>
  • Functions are declared with fun, take up to 255 parameters, and are called with up to 255 arguments.
  • The argument count must match exactly: Expected 2 arguments but got 1.
  • A function without a return (or with a bare return;) returns nil.
  • return at the top level is a compile error.
  • Call depth is capped at 64 frames. Deeper recursion fails with Stack overflow.

Language

Closures

A function can use variables from enclosing functions, and keep using them after those functions have returned.

fun makeCounter() {
  var i = 0;
  fun count() {
    i = i + 1;
    return i;
  }
  return count;
}

var c = makeCounter();
print c();   // 1
print c();   // 2

Here count captures i, which would normally vanish when makeCounter returns. gholang keeps it alive using upvalues.

Language

Native functions

The VM registers one native function at startup:

FunctionReturns
clock()CPU time used by the process, in seconds, as a number.
var start = clock();
// … work …
print clock() - start;

Natives are C functions with the signature Value fn(int argCount, Value *args). They aren't arity-checked by the VM, so a native must validate its own arguments. To add one, write the function in vm.c and register it in initVM():

defineNative("clock", clockNative);

Internals

The pipeline

Source text goes through three stages. The first two are interleaved: the compiler pulls tokens from the scanner on demand.

Sourcechar *
→
Scannerscanner.c
→
Compilercompiler.c
→
Chunkbytecode
→
VMvm.c

The entry point is interpret() in vm.c:

InterpretResult interpret(const char *source)
{
    ObjFunction *function = compile(source);
    if (function == NULL)
        return INTERPRET_COMPILE_ERROR;

    push(OBJ_VAL(function));
    ObjClosure *closure = newClosure(function);
    pop();
    push(OBJ_VAL(closure));
    call(closure, 0);

    return run();
}

The whole program is compiled as an implicit top-level function called <script>, wrapped in a closure and called with zero arguments. That's why the top level and functions share the same machinery.

Internals

Scanner

scanner.c turns characters into tokens lazily: scanToken() returns one token per call and never builds a list. A token doesn't copy text. It points into the source string:

typedef struct
{
    TokenType type;
    const char *start;   // into the source
    int length;
    int line;
} Token;
  • Whitespace and // comments are skipped; newlines bump the line counter.
  • Keywords are recognised with a hand-written trie in identifierType(): switch on the first letter, then compare the rest with memcmp.
  • Errors are returned as a TOKEN_ERROR whose start points at the message.

The language has 16 keywords: and class else false for fun if nil or print return super this true var while, though class, super and this don't do anything yet.

Internals

Compiler

compiler.c is the biggest file. It is a single-pass compiler: it parses and emits bytecode at the same time, with no syntax tree in between.

Pratt parsing

Expressions use a Pratt parser driven by a table. Each token type has an optional prefix function, an optional infix function and a precedence:

typedef struct
{
    ParseFn prefix;
    ParseFn infix;
    Precedence precedence;
} ParseRule;

ParseRule rules[] = {
    [TOKEN_LEFT_PAREN] = {grouping, call,   PREC_CALL},
    [TOKEN_MINUS]      = {unary,    binary, PREC_TERM},
    [TOKEN_PLUS]       = {NULL,     binary, PREC_TERM},
    [TOKEN_AND]        = {NULL,     and_,   PREC_AND},
    // …
};

parsePrecedence(p) parses the prefix expression, then keeps consuming infix operators while their precedence is at least p. For left-associativity, binary() parses its right operand at precedence + 1.

Assignment

Each parse function receives canAssign, which is true only when we're parsing at assignment precedence or lower. That's how a + b = c is rejected as Invalid assignment target while a = c works.

Desugaring

Some operators don't have their own opcode. The compiler emits a pair:

SourceEmitted
a != bOP_EQUAL, OP_NOT
a <= bOP_GREATER, OP_NOT
a >= bOP_LESS, OP_NOT

Jumps

Control flow uses backpatching. emitJump() writes the opcode and a two-byte placeholder (0xffff) and returns its position. Once the target is known, patchJump() fills in the real distance. Backward jumps (OP_LOOP) already know their target, so emitLoop() computes the offset directly.

One compiler per function

Each function being compiled gets a Compiler struct holding its locals, upvalues and scope depth. They form a linked list through enclosing, and the global current points to the innermost. Slot 0 of every function is reserved for the callee itself.

Internals

Chunks & bytecode

A chunk is a function's compiled body. It's three parallel dynamic arrays:

typedef struct
{
    int count;
    int capacity;
    uint8_t *code;          // opcodes and operands
    int *lines;             // source line of each byte
    ValueArray constants;   // literals and names
} Chunk;

Arrays grow by doubling (minimum 8) through GROW_CAPACITY and reallocate(). The lines array runs parallel to code, which is how runtime errors report a line number.

The constant pool

Literals and variable names don't sit inside the instruction stream. They're stored in constants, and instructions refer to them by a one-byte index. That caps a chunk at 256 constants.

Example

For print 1 + 2 * 3;, the disassembler prints:

== <script> ==
0000    1 OP_CONSTANT         0 '1'
0002   |OP_CONSTANT         1 '2'
0004   |OP_CONSTANT         2 '3'
0006   |OP_MULTIPLY
0007   |OP_ADD
0008   |OP_PRINT
0009    2 OP_NIL
0010   |OP_RETURN

The columns are: byte offset, source line (| means same as above), opcode, then the operand and the constant it refers to. The final OP_NIL / OP_RETURN is the implicit return every function gets.

Internals

The VM

There's one global VM struct. Its important fields:

typedef struct
{
    CallFrame frames[FRAMES_MAX];   // 64
    int frameCount;

    Value stack[STACK_MAX];         // 64 * 256
    Value *stackTop;                // one past the last value
    ObjUpvalue *openUpvalues;
    Table globals;
    Table strings;                  // interned strings
    Obj *objects;                   // every allocated object
} VM;

The run loop

run() is a for (;;) loop around a switch on the next opcode. Reading helpers are macros over the current frame's instruction pointer (READ_BYTE, READ_SHORT, READ_CONSTANT), and arithmetic shares a BINARY_OP macro.

The stack

stackTop points one past the last value. push writes then advances, and pop decrements then reads. Executing 1 + 2 * 3 looks like this:

          [ <script> ]
0000    1 OP_CONSTANT         0 '1'
          [ <script> ][ 1 ]
0002   |OP_CONSTANT         1 '2'
          [ <script> ][ 1 ][ 2 ]
0004   |OP_CONSTANT         2 '3'
          [ <script> ][ 1 ][ 2 ][ 3 ]
0006   |OP_MULTIPLY
          [ <script> ][ 1 ][ 6 ]
0007   |OP_ADD
          [ <script> ][ 7 ]
0008   |OP_PRINT
7

The leading <script> is the top-level closure sitting in slot 0.

Call frames

Every call creates a CallFrame:

typedef struct
{
    ObjClosure *closure;
    uint8_t *ip;      // this frame's own instruction pointer
    Value *slots;     // first stack slot this function owns
} CallFrame;

The callee and its arguments are already on the stack when OP_CALL runs, so slots just points at the callee's slot. Locals are then addressed as slots[n], which is why the compiler can resolve them to plain numbers. On OP_RETURN the stack is truncated back to slots, the result is pushed, and the previous frame resumes.

Natives

callValue() dispatches on object type. Closures push a frame. Natives are called immediately, and their arguments and the callee are replaced by the result.

Internals

Values & objects

Tagged union

A Value is a type tag plus a union. Numbers, booleans and nil are stored inline. Everything else is a pointer to a heap Obj.

typedef struct
{
    ValueType type;     // VAL_BOOL, VAL_NIL, VAL_NUMBER, VAL_OBJ
    union
    {
        bool boolean;
        double number;
        Obj *obj;
    } as;
} Value;

Macros wrap it: NUMBER_VAL(x) builds a value, IS_NUMBER(v) checks the tag and AS_NUMBER(v) unwraps. Only use AS_ after an IS_ check.

Heap objects

Every object begins with an Obj header, so a pointer to any of them can be treated as an Obj * (struct inheritance in C). The header holds the type tag and a next pointer; all objects form a linked list from vm.objects so they can be freed at shutdown.

TypeStructHolds
OBJ_STRINGObjStringlength, char *, cached hash
OBJ_FUNCTIONObjFunctionarity, upvalue count, Chunk, name
OBJ_CLOSUREObjClosurefunction and array of ObjUpvalue *
OBJ_UPVALUEObjUpvaluepointer to a captured variable, plus a slot for when it's closed
OBJ_NATIVEObjNativeC function pointer

String interning

Every string is interned: vm.strings maps each distinct string to its single ObjString. Creating a string first hashes it (FNV-1a) and looks it up. If a match exists, it is reused. As a result:

  • String equality is a pointer comparison.
  • Hash-table lookups never need memcmp.
  • Concatenation allocates a buffer, then hands it to takeString(), which frees the buffer if an identical string already exists.
Memory

All allocation goes through reallocate() in memory.c. There's no garbage collector yet, so objects live until freeVM() calls freeObjects() at exit.

Internals

Hash tables

table.c is an open-addressing hash map from ObjString * to Value. It backs both global variables and the string intern set.

  • Probing: linear. The index is hash % capacity, advancing by one on collision.
  • Load factor: grows when it would exceed 0.75. Capacity starts at 8 and doubles.
  • Deletion: uses tombstones (a NULL key with a true value) so probe chains stay intact. Tombstones count toward the load factor.
  • Keys compare by pointer thanks to interning. tableFindString() is the one place that compares characters, and it's what implements the interning.
FunctionPurpose
tableGetlook up a key; returns whether it was found
tableSetinsert or overwrite; returns true if the key is new
tableDeletereplace the entry with a tombstone
tableAddAllcopy every entry from one table into another
tableFindStringfind an interned string by content and hash

OP_SET_GLOBAL uses the return value of tableSet neatly: if it reports a new key, the variable didn't exist, so the entry is deleted again and a runtime error is raised.

Internals

Upvalues

Closures are the hardest part of the VM. A local lives on the stack, but a closure may need it after its function returns. gholang solves this with upvalues.

At compile time

When a name isn't a local, resolveUpvalue() looks in the enclosing function:

  1. If the enclosing function has it as a local, mark that local isCaptured and record an upvalue with isLocal = true.
  2. Otherwise recurse outward. If found there, record an upvalue with isLocal = false that points at the enclosing function's own upvalue.
  3. If nothing matches, it's a global.

The list of (isLocal, index) pairs is emitted right after OP_CLOSURE. This is the real bytecode for the counter example from Closures:

== count ==
0000    3 OP_GET_UPVALUE      0
0002   |OP_CONSTANT         0 '1'
0004   |OP_ADD
0005   |OP_SET_UPVALUE      0
0007   |OP_POP
0008   |OP_GET_UPVALUE      0
0010   |OP_RETURN

== makeCounter ==
0000    2 OP_CONSTANT         0 '0'
0002    3 OP_CLOSURE          1 <fn count>
0004      |                     local 1
0006    4 OP_GET_LOCAL        2
0008   |OP_RETURN

local 1 means: capture the enclosing function's local in slot 1 (i; slot 0 is the function itself).

At runtime

When OP_CLOSURE executes, captureUpvalue() creates an ObjUpvalue that points at the stack slot. Open upvalues are kept in a list sorted by stack address, so two closures that capture the same variable share one upvalue and see each other's writes.

When a captured local goes out of scope, the compiler emits OP_CLOSE_UPVALUE instead of OP_POP (and OP_RETURN closes everything in its frame). closeUpvalues() copies the value into the upvalue's own closed field and repoints location at it. From then on the variable lives on the heap, and the closure doesn't notice the move.

Internals

Debugging

Two compile-time flags in common.h turn on the built-in tooling:

FlagEffect
DEBUG_PRINT_CODEAfter each function is compiled (if there were no errors), print its disassembly.
DEBUG_TRACE_EXECUTIONBefore every instruction, print the stack contents and the disassembled instruction.

debug.c provides disassembleChunk() and disassembleInstruction(). There are three instruction shapes to print: simple (no operand), constant (index plus the value), and byte (raw operand), plus special handling for jumps (shows the target offset) and OP_CLOSURE (lists the captures).

To add an opcode, you touch four places: the enum in chunk.h, run() in vm.c, disassembleInstruction() in debug.c, and whichever compiler function emits it.

Grammar

The grammar that the compiler actually accepts, in the notation of the book.

program     → declaration* EOF ;

declaration → funDecl | varDecl | statement ;
funDecl     → "fun" IDENTIFIER "(" parameters? ")" block ;
parameters  → IDENTIFIER ( "," IDENTIFIER )* ;
varDecl     → "var" IDENTIFIER ( "=" expression )? ";" ;

statement   → exprStmt | forStmt | ifStmt | printStmt
            | returnStmt | whileStmt | block ;
exprStmt    → expression ";" ;
forStmt     → "for" "(" ( varDecl | exprStmt | ";" )
                        expression? ";" expression? ")" statement ;
ifStmt      → "if" "(" expression ")" statement ( "else" statement )? ;
printStmt   → "print" expression ";" ;
returnStmt  → "return" expression? ";" ;
whileStmt   → "while" "(" expression ")" statement ;
block       → "{" declaration* "}" ;

expression  → assignment ;
assignment  → IDENTIFIER "=" assignment | logic_or ;
logic_or    → logic_and ( "or" logic_and )* ;
logic_and   → equality ( "and" equality )* ;
equality    → comparison ( ( "!=" | "==" ) comparison )* ;
comparison  → term ( ( ">" | ">=" | "<" | "<=" ) term )* ;
term        → factor ( ( "-" | "+" ) factor )* ;
factor      → unary ( ( "/" | "*" ) unary )* ;
unary       → ( "!" | "-" ) unary | call ;
call        → primary ( "(" arguments? ")" )* ;
arguments   → expression ( "," expression )* ;
primary     → "true" | "false" | "nil" | NUMBER | STRING
            | IDENTIFIER | "(" expression ")" ;
